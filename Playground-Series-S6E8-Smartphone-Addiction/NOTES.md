## Data observations

- Train: 691,369 rows; test: 296,302 rows; 12 predictors.
- Positive rate: 0.709424.
- All predictors contain missing values; missingness rates differ between train
  and test for several columns.
- Strongest raw numeric associations: daily screen time, weekend screen time,
  and social-media hours.
- Synthetic accounting identity: daily screen time is composed from social,
  gaming, work/study, and residual usage. Composition features are therefore
  reasonable, but their interpretation is synthetic rather than causal.
- Continuous values repeat heavily, making leakage-safe nested target/frequency
  encoding a promising representation.
- The 7,500-row source dataset has a different dependency structure and should
  be used for diagnostics, not augmentation.

## Active hypotheses

1. Nested target and frequency encodings for every repeated numeric/categorical
   value can expose smooth conditional target structure without leakage.
2. Retaining raw NaNs alongside imputed values preserves native missing-value
   routing while enabling complete composition and ratio features.
3. XGBoost, LightGBM, and CatBoost errors should be combined using OOF-trained
   logit stacking or rank blending, never leaderboard-selected arbitrary weights.
4. Missing-count regimes may require different calibration or ensemble weights.

### E005 — Private nested target/frequency encoding + XGBoost

- Provenance: implemented from scratch for this project; reads only the attached
  competition `train.csv`, `test.csv`, and `sample_submission.csv`.
- Validation: 4-fold stratified outer OOF. Within each outer training fold,
  target encodings for model-training rows are generated by a separate 4-fold
  inner split. Outer validation and test encodings use mappings fitted only on
  that outer fold's training rows.
- Features: raw predictors, missing count/pattern, exact-value frequency and
  smoothed target encoding for every raw/engineered column, screen-time
  composition sums/residuals/shares, weekend/daily contrasts, and behavioral
  ratios.
- Model: XGBoost histogram trees, GPU requested with automatic CPU fallback;
  early stopping independently in every outer fold.
- Leakage controls: no public prediction datasets, no validation labels in
  encoders, and genuine held-out predictions for every OOF row.
- Kaggle kernel: `boltuzamaki/s6e8-nested-te-xgboost-private` (private).
- Result: completed successfully on Kaggle GPU in about 4.9 minutes. Fold AUCs
  were `0.96811181`, `0.96799757`, `0.96799973`, and `0.96754461`; full OOF
  AUC was **0.96790968**. Best boosting iterations were 1,434, 1,433, 1,560,
  and 1,729.
- Observation: the folds are consistent (range 0.00057), supporting a genuine
  improvement over the raw CatBoost baseline rather than a lucky holdout.
  Target/frequency representations work, but OOF remains below the 0.97069
  public-prediction benchmark. The fourth model was capped at 1,800 trees, so a
  slightly larger tree budget or lower learning rate is worth testing.
- Artifacts: `artifacts/kaggle_te_xgb/metrics.json`, genuine OOF predictions,
  test predictions, and the complete kernel log. No competition submission was
  authorized or made from this experiment.

### E013 — Exact missing-pattern error audit and conditional gate

- Added `ensemble_original/analyze_missing_slices.py`. It reconstructs the
  guarded core prediction by five-fold meta-crossfit, audits all exact missing
  patterns with at least 5,000 rows, audits per-feature availability, and saves
  row-aligned diagnostics and residual summaries. Public predictions are not read.
- Error difficulty rises monotonically with missing count: core AUC is
  `0.97590893` for complete rows, `0.97218815` with one missing field,
  `0.96461446` with two, `0.95334013` with three, `0.93937970` with four,
  `0.92058561` with five, and `0.90269916` with six. Mean absolute residual rises
  from `0.11121` when complete to `0.22546` at six missing fields.
- No existing alternative beats the core outright on any audited large exact
  pattern. Two alternatives narrowly beat standalone XGB5: representation
  LightGBM global on exactly notifications + app opens missing (`7,753` rows,
  `+0.000270` AUC versus XGB5), and LGB-TE on exactly daily screen time missing
  (`13,183` rows, `+0.000152`). LGB-TE is also `+0.000019` over XGB5 when exactly
  notifications + app opens are missing. All remain below the core blend.
- Three exploratory blend niches were tested: exactly daily screen time missing
  with CPU CatBoost, exactly social + gaming missing with raw XGBoost, and exactly
  notifications + app opens missing with representation global LightGBM. Their
  in-slice whole-OOF best logit-blend gains were only `+0.000166`, `+0.000092`,
  and `+0.000090`, respectively, and are hypothesis-generating only.
- The fixed pattern definitions were then evaluated with alternative weights

### E041 — NODE-style differentiable oblivious trees (prepared, not launched)

- First neural oblivious decision ensemble in the experiment ledger. Sixty-four
  depth-5 soft trees learn a differentiable feature choice and threshold at
  each depth, route examples probabilistically to 32 leaves, then learn an
  ensemble weight. There is no MLP tower, cross layer, feature gate, attention,
  embedding interaction, or retrieval component.
- Official tables only, with target-free composition features and outer-fit-
  local quantiles, medians and categorical one-hot levels. Honest stratified
  five-fold OOF and a fixed 20-epoch configuration keep outer labels strictly
  reporting-only.
- The 64-tree routing tensor, batch size 2,048 and 8,192-row inference batches
  are sized for the local RTX 4060. Outputs are explicitly isolated under
  `local_node_oblivious/output/`; the optional Kaggle metadata remains private
  and offline. No launch or submission occurred.
- PyCompile, soft-selection normalization, label-invariance, finite-gradient,
  and a full one-epoch fold train/predict smoke test pass. The artifact contract
  includes OOF, test predictions, metrics and learned feature-selection weights.

### S004 — Cross-fitted logistic stack over the full stream inventory

- Every prior deployment hand-tuned a rank average over about ten streams while
  the repository held more than forty completed own-model OOF/test pairs. The
  new `ensemble_original/mega_stack.py` validates the whole inventory (ID order,
  coverage, finiteness, provenance), gauss-rank normalises each stream so tree
  and neural calibrations are comparable, and cross-fits an L2 logistic
  meta-learner.
- 26 usable streams reached cross-fitted OOF `0.9695782`; repairing ten column
  mismatches lifted this to 40 streams and OOF `0.9696223`. Submission
  `55301421` scored public LB **`0.97060`**, improving the previous own best
  `0.97029` by `+0.00031`.
- Hill climbing over the same matrix reached only `0.9694472`, so the linear
  meta-learner is retained.

### S005 — Bagged weights plus the first fold-safe stream

- `ensemble_original/stack_weights.py` compares weight-fitting schemes on the
  cached stream matrix. Non-negative least squares was tested on the hypothesis
  that 25 tree streams at 0.99+ mutual correlation invite offsetting weights;
  it scored `0.9689162`, far worse than unconstrained logistic. The hypothesis
  is rejected and unconstrained weights are retained.
- Bagging the logistic fit over resampled meta-training subsets plus the new
  fold-safe TE XGBoost stream gave 42 streams at OOF `0.9696482`. Submission
  `55302817` scored **`0.97062`**.

### Calibration — public LB equals cross-fitted OOF plus 0.00099

- Three independent points now agree within `0.00002`: S003 OOF `0.9692864` ->

### E042 — Fold-safe OOF target encoding (the published notebook's defect)

- The public notebook's `__te` columns are fitted on the same rows the model
  trains on, so every training row sees its own label while test rows never do.
  `gpu_foldsafe_te_xgb/` keeps the rich composition view and repairs the
  encoding: fit rows receive inner out-of-fold rates from label-independent
  folds, while outer-validation and test rows are mapped from the complete
  outer-fit partition.
- Kaggle GPU run: pooled OOF **`0.9682418`** in 20 minutes, beating every
  existing XGBoost stream (`xgb_hpo_d7` `0.9681336`) and within `0.0001` of the
  best single own model. All five folds selected `d7_regular`.
- `publish_lgbm_end_to_end/test_encoding_contract.py` passes six executable
  checks, including independent reconstruction of the encoding and a
  prior-preserving label swap that isolates own-label exclusion from the
  smoothing shift. Note that a naive flip test is confounded: flipping one label
  moves the smoothing prior and therefore every encoded value.

### Diversity audit — the tree family is saturated

- Spearman correlation of the new fold-safe TE XGBoost with existing streams:
  `xgb_hpo_d7` `0.9961`, `lgb_pair_lattice` `0.9950`, `cat_dual_view` `0.9903`,
  but `lookup_v2_s42` only `0.9756`.
- A plain 50/50 rank blend of fold-safe TE XGBoost with the lookup transformer
  reaches `0.9691730`, versus `0.9684932` when blended with the existing
  XGBoost. Every GBDT variant duplicates signal already held; the exact-value
  lookup transformer is the only materially decorrelated family.
- This also explains the four target-free neural runs (DCNv2 `0.9385`, GANDALF
  `0.9387`, FT-Transformer `0.9401`, TabR `0.9380`): the dataset requires target
  information, which the lookup transformer encodes implicitly through
  exact-value embeddings. Further target-free architectures are not worth GPU
  time; additional lookup-transformer seeds are.
